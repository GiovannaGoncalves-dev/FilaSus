# FilaSUS — regras de estilo herdadas

Escaneamento inicial: 57 arquivos-fonte (tier médio). Referência: estado visual anterior à migração JSP.

## Golden Files

- `src/main/webapp/css/styles.css`: tokens, shell, sidebar, header, cards, tabelas, badges, estados e responsividade.
- `src/main/webapp/jsp/atendente/dashboard.jsp` no `HEAD`: composição de dashboard, cards de fila e estados operacionais.
- `src/main/webapp/jsp/paciente/dashboard.jsp` no `HEAD`: hierarquia visual da área do paciente.
- `src/main/webapp/jsp/painel.jsp` no `HEAD`: painel de exibição em tela cheia.
- `src/main/webapp/jsp/login.jsp` no `HEAD`: linguagem visual das telas públicas.

## Naming & State-Control Rules

- Reutilizar classes do design system; CSS específico só complementa o que não existe.
- Páginas autenticadas usam shell consistente: navegação lateral, conteúdo principal, cabeçalho e usuário.
- Conteúdo de negócio é renderizado por JSP; JavaScript fica restrito a apresentação e interação visual.
- Formulários usam `input`, `select`, `field`, `btn` e variantes já existentes.
- Estados vazio, erro e sucesso usam `empty-state`, `alert` e badges semânticos.
- Layouts devem continuar responsivos nos breakpoints existentes.

## DONTs

- Não substituir o design system por HTML cru ou estilos compactados de página única.
- Não achatar sidebar/cards/tabelas em uma lista genérica.
- Não recriar APIs JSON, `fetch()` ou renderização de dados via `innerHTML`.
- Não misturar URLs diretas de JSP com as rotas canônicas dos controllers.
- Não remover detalhes visuais existentes apenas para simplificar a implementação server-side.
